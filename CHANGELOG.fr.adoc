== v0.2.1 — 2026-04-29

=== Modifié

* **Repo GitHub renommé** vers `aloli-crystal/clevis-zfs` (convention
  de nommage Aloli : les créations originales abandonnent le préfixe
  `crystal-`). Les anciens liens redirigent automatiquement.
* Champ `name:`, cible de compilation et binaire CLI alignés sur le
  nouveau nom du repo. Shim d'entrée renommé `src/clevis-zfs.cr`
  (charge toujours `src/crystal_clevis_zfs.cr`, le code).
* Dépendance vers JOSE mise à jour sur la nouvelle URL
  (`aloli-crystal/jose`). Chemins `require` adaptés.
* Le module interne `Clevis` et le dossier `src/crystal_clevis_zfs/`
  restent inchangés — nettoyage reporté.

== v0.2.0 — 2026-04-27

Surface CLI pour le multi-Tang et l'enrôlement de clé existante.

* CLI : `bind` accepte `--tang URL` répétable et `--threshold K`.
  Bascule en single-Tang si une seule URL est fournie avec
  threshold 1 (ou omis) — rétrocompatible avec les appels v0.1.
* CLI : `bind --use-existing-key` enrôle la clé d'un dataset déjà
  chiffré (uniquement quand `keylocation=file://...`). Lit la
  clé du fichier (64 chars hex ou 32 octets bruts), la pousse à
  travers Tang, écrit le JWE. Utile pour migrer d'Option C
  (`mode: ssh_unlock`) vers Option D (`mode: tang`).
* `Zfs.get_property` exposée publiquement (était inlinée dans
  `keystatus`).

Pas de changement cassant : un JWE v0.1 reste lisible par
`unlock`, et le `bind --init` single-Tang v0.1 continue à
produire le même format JWE.

== v0.1.0 — 2026-04-27

Première version publiée. Successeur de `crystal-clevis-geli`
(déprécié), utilisant le chiffrement natif ZFS au lieu de GELI.

* **Module `Zfs`** : enrobage léger de `zfs(8)` pour
  `create_encrypted`, `load_key`, `unload_key`, `change_key`,
  `key_loaded?`, `encrypted?`, `mount_recursive`. La clé est
  passée à ZFS via stdin uniquement, jamais via argv ni env.
* **Module `TangClient`** (réutilisé depuis `crystal-clevis-geli`
  v0.1) : bind/recover ECDH-ES contre un serveur Tang.
* **Module `SssBinder`** + **`Sss`** (réutilisés) : Shamir Secret
  Sharing pour multi-Tang threshold N-of-M. Le code est présent
  et testé mais le CLI v0.1 n'expose que le single-Tang ; la
  surface CLI multi-Tang complète arrive en v0.2.
* **CLI** : `bind` (single-Tang via `--init`), `unlock`
  (auto-détecte SSS vs single-Tang depuis l'en-tête JWE),
  `version`, `help`.
* **rc.d** pour le déverrouillage automatique au boot.
* **Tests** : 47 examples (tests unitaires + round-trips Sss +
  SssBinder + EcArithmetic + TangClient mock + Zfs avec un
  faux `zfs(8)` en script shell).

=== Note sur le prédécesseur GELI

`crystal-clevis-geli` v0.1 (et sa v0.2 avec SSS multi-Tang) reste
utilisable mais n'est plus le chemin recommandé pour les
déploiements FreeBSD + ZFS. Voir
`crystal-clevis-zfs-specs.adoc` dans `beryl` pour la
justification.
